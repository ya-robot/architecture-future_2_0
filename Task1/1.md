### **Проблемные места в текущей и будущей архитектуре «Будущее 2.0»**  

#### **1. Узкие места и риски**  
| **Проблема**               | **Последствия для бизнеса**                          | **Решение** |
|----------------------------|----------------------------------------------------|-------------|
| **Медленные отчёты** (из-за монолитного DWH) | Задержки в принятии решений, фрустрация аналитиков | Переход на облачное DWH (Snowflake/BigQuery) |
| **Сложная интеграция новых бизнесов** (например, фармацевтики) | Долгий time-to-market, высокие затраты на доработки | Data Mesh + API-шлюзы |
| **Устаревший интерфейс** (Power Builder) | Низкая скорость работы врачей, ошибки ввода данных | Миграция на веб-интерфейс (React/Angular) |
| **Негибкая аналитика** (зависимость от IT) | Бизнес не может быстро проверять гипотезы | Self-Service BI (Power BI + конструктор отчётов) |
| **Юридические риски** (GDPR, HIPAA) | Штрафы из-за утечек медицинских данных | Разделение данных + Azure AD + аудит |

---

#### **2. Технический долг**  
| **Что устарело?**          | **Чем это мешает?**                                | **Как исправить?** |
|----------------------------|----------------------------------------------------|-------------------|
| SQL Server 2008            | Не поддерживает современные форматы данных, медленный | Миграция в облако |
| Apache Camel (шина данных) | Трудно масштабировать, нет поддержки событийной модели | Замена на Kafka |
| Локальные BI-отчёты        | Нет кросс-доменной аналитики, сложно делиться данными | Единый портал аналитики |

---

#### **3. Риски при переходе на новую архитектуру**  
| **Риск**                   | **Как минимизировать?** |
|----------------------------|-------------------------|
| **Сопротивление сотрудников** (врачи, финансисты привыкли к старым системам) | Постепенная миграция + обучение |
| **Недостаток данных для ИИ** (модели требуют качественных датасетов) | Интеграция Data Lake с ИИ-сервисами |
| **Высокая стоимость облачных сервисов** | Оптимизация запросов + мониторинг затрат |

---

### **Вывод для бизнеса**  
**Главные боли:**  
1. **Скорость аналитики** – сейчас отчёты строятся часами, это тормозит решения.  
2. **Жёсткая связность систем** – добавление фармацевтики или новых клиник будет дорогим.  
3. **Юридические риски** – данные врачей и банковские транзакции требуют чёткого контроля.  

**Что делаем:**  
- Внедряем **облачные технологии** (Snowflake, Kafka) для скорости и масштабируемости.  
- Даём бизнесу **инструменты самообслуживания** – чтобы не ждать IT.  
- Сохраняем **легаси-системы** там, где риски перевешивают пользу.  

Это сократит затраты на поддержку и ускорит выход новых продуктов.
